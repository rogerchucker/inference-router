| Environment | Application pipeline | Terraform pipeline | Lifecycle |
|---|---|---|---|
| **CI runner** | Lint, unit-test, build, and run container-based integration tests. Use kind when you need Kubernetes behavior. | Format, validate, test modules, and generate plans for affected environments. | Disposable per run. Most PRs need no AWS deployment. |
| **PR preview / sandbox** | Deploy a branch to a temporary namespace on a shared non-production cluster when a live preview is useful. | Create temporary AWS resources when a change needs real AWS validation. Use a dedicated sandbox account and isolated state. | Tear down on PR close or test completion. Use a TTL to catch missed cleanup. |
| **Shared dev / integration** | Deploy frequently from `main` for cross-service integration. | Apply reviewed changes to the dev foundation. | Optional. Keep it if teams depend on stable endpoints. Scale down idle workloads and compute where possible. |
| **Staging / pre-prod** | Deploy the candidate image digest, run smoke and end-to-end tests, and verify rollout and rollback behavior. | Apply infrastructure changes here before production where practical. Validate the resulting infrastructure. | Usually persistent. Keep the production mechanisms you’re trying to test, with smaller capacity and synthetic data. |
| **Production** | Promote the same tested digest after approval. Argo CD reconciles it, and you verify service health. | Apply a separately reviewed **production** plan using production credentials and state. | Persistent. Replace components through controlled changes. Practice full rebuild and restore in an isolated environment. |
